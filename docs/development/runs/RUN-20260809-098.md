# RUN-20260809-098 — RC9.3 bounded CISO token-revocation browser journey

Date: 2026-08-09
Roadmap phase: 6 — Frontend accessibility and operational UX
Objective: implement one critical CISO browser journey for governed security-token revocation with backend RBAC consistency and persistent operational evidence.

## Plan

Blocking gates for this bounded objective:

- browser-visible token revocation capability must derive from backend-resolved `revoke:tokens` permission;
- an `analyst` principal must not see the revocation control;
- a direct analyst browser request to the backend revocation endpoint must return `403`;
- a `ciso` principal must be able to revoke one synthetic future-expiry token through the real backend endpoint;
- Redis must persist the revoked token state;
- PostgreSQL must persist an immutable `token.revoke` audit event bound to the human CISO principal and provenance;
- the persisted audit chain must remain valid;
- review, share approval and publication behavior must remain unchanged;
- all repository-required exact-head workflows plus the dedicated RC9.3 browser workflow must execute successfully before PASS;
- missing, queued or unexecuted CI is never PASS;
- issue #1 external production gates remain independent and open.

Responsive behavior, keyboard navigation, cross-browser coverage, broad WCAG 2.2 AA validation, auditor workflow breadth, production identity-provider acceptance and secrets-manager acceptance are explicitly outside this run.

## Do

Implemented:

- `backend/dtmo/ciso_ui.py` with `/ui/ciso-security` and a no-store/CSP-constrained browser surface;
- backend-derived capability gating using the existing `/api/v1/ui/session` response;
- a governed revocation form posting only to the existing `/api/v1/security/tokens/revoke` endpoint;
- registration of the CISO UI router in `backend/dtmo/main.py`;
- `backend/tests/test_rc9_3_browser_ciso_token_revocation.py` with Chromium paths for analyst UI denial, analyst direct-backend `403`, CISO success, Redis verification and persistent audit-chain verification;
- `.github/workflows/browser-ciso-token-revocation-e2e.yml` with PostgreSQL and Redis services, Chromium installation, migrations, retained JUnit/server/machine-readable evidence and a fail-closed gate job;
- `docs/qa/RC9_3_CISO_TOKEN_REVOCATION_GATE.md`.

No production dependency, live connector, intelligence source, publication rule or share-approval rule was changed.

## Check

Current decision at implementation cutoff: `CI_VALIDATION_PENDING`.

The new dedicated workflow has not yet been accepted as PASS. Exact-head GitHub Actions and retained `browser-ciso-token-revocation-evidence` must execute and be independently inspected. No local or unexecuted test is recorded as release evidence.

Security/governance review confirms the implementation uses the existing backend `REVOKE_TOKENS` permission and existing token-revocation/audit service rather than duplicating authorization logic in the browser. The browser only controls visibility; backend authorization remains authoritative.

## Threat, CVE and vendor context

RC9.3 introduces no new production dependency or external provider. Redis, PostgreSQL and Playwright/Chromium are already part of the existing platform/test architecture. Existing dependency review, container, secrets and quality gates remain authoritative. No new public threat-intelligence, historical education-incident, CVE or vendor-advisory finding materially changes this bounded UI/RBAC objective; any material finding surfaced by those gates blocks acceptance rather than being waived here.

## Act

Lesson: a critical CISO journey should prove not only UI visibility but also server-side denial, operational state change and durable audit evidence. RC9.3 therefore treats browser rendering alone as insufficient.

Decision: `CI_VALIDATION_PENDING`.

Exactly one next priority: inspect every required workflow on the final RC9.3 PR head and independently inspect retained `browser-ciso-token-revocation-evidence`; repair only the first deterministic failure, or accept/merge only after complete successful exact-head evidence.

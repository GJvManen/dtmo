# RUN-20260806-025 — RC5.3 trusted principal token validation

## Plan

- **Roadmap phase:** Phase 2 — Application security and identity.
- **Bounded objective:** stop production trust in caller-supplied subject and role headers by resolving principals from signed bearer-token claims.
- **Blocking gates:** issuer, audience, signature and temporal claims must be validated; machine and human identities may not cross role boundaries; production must reject unsigned identity headers; all existing quality gates must execute successfully.
- **Governance:** RBAC, service-account isolation, separate review/share approval and human publication approval remain unchanged.

## Do

- Added `PyJWT` as the token verification dependency.
- Added required signed claims: `sub`, `roles`, `principal_type`, `jti`, `iss`, `aud`, `iat`, `nbf`, `exp`.
- Restricted accepted algorithm to `HS256` for this bounded implementation.
- Added explicit human, service-account, connector and scheduler principal types.
- Required machine identities to use only the `service_account` role and prohibited that role for human tokens.
- Added production configuration for signing secret, issuer and audience.
- Changed production principal resolution to require a bearer token; legacy identity headers remain development-only for compatibility.
- Added positive and negative regression tests.

## Check

- Repository changes and tests are committed on `rc5/rc5-3-trusted-principal-tokens`.
- No local or GitHub Actions test execution is claimed at commit time.
- The exact PR-head Quality Gate is required before PASS.

## Act

- **Lesson:** identity-bearing headers are authorization input only when established by a hardened trusted proxy; direct client headers cannot establish production identity.
- **Run decision:** `CI_VALIDATION_PENDING`.
- **Exactly one next priority:** inspect the first completed Quality Gate for the exact RC5.3 PR head and resolve only its earliest deterministic failure, or merge after full success.

# RUN-20260810-162 — DTMO 16.0.0rc6 professional frontend UX overhaul

## Plan

**Objective:** replace the merely functional rc5 frontend experience with one coherent professional operator UX across the primary console and specialized role surfaces, without changing DTMO's authorization, separation-of-duties, privacy, auditability or human-share-approval invariants.

Blocking gates:

- all existing server-side RBAC behavior must remain authoritative;
- review and external share approval must remain separate governed actions;
- audit evidence must remain read-only;
- no credentials, tokens or secret material may be embedded or persisted outside the existing local/dev/staging per-tab helper;
- accessibility regressions must be protected by repository tests/workflows;
- final exact-head CI must complete successfully before merge;
- external VoiceOver/NVDA, real staging and external assurance evidence remain separate blockers.

## Do

Implemented 16.0.0rc6 on `release/16.0.0rc6-ux`:

- redesigned `/` and `/ui/console` into a professional Threat Operations Console;
- introduced stable information architecture: Overview, Intelligence, Governance, Audit and Security;
- added responsive sidebar/mobile navigation, KPI cards, status pills, structured loading/error/empty states and an identity dialog;
- reworked intelligence results into structured analyst cards;
- reworked governed decisions into explicit Review and External Share Approval steps;
- reworked audit evidence into a read-only table;
- isolated CISO token revocation as a privileged security operation;
- modernized `/ui/analyst-search`, `/ui/share-approval`, `/ui/auditor` and `/ui/ciso-security` using the shared design system;
- retained CSP/no-store protections and browser-tab-only local/dev/staging identity helper;
- bumped application/package version to `16.0.0rc6`;
- expanded frontend regression tests;
- added `docs/ux/FRONTEND_UX.md` and rc6 release notes.

## Check

Production-facing security software needs a deliberate information architecture, role-specific task flows, clear state communication and a shared visual/interaction system in addition to technical accessibility controls.

External UX/accessibility testing should now use rc6 rather than rc5 because rc6 is the intended operator-facing baseline.

# RUN-20260828-382 — R4 integrated enrichment contract

## Scope

This bounded R4 recovery slice codifies the repository-controlled contract already present across IOC Explorer, Analysis & Enrichment, IntelOwl persistence and Cortex persistence.

Persisted observables are exposed only from governed enrichment evidence. IOC context carries the canonical item identifier plus the persisted observable type/value into Analysis; Threat Intelligence object context carries the canonical item identifier into the same governed Analysis workspace. Analysis reloads persisted history through the same-origin DTMO API and reloads that history after explicit authorized execution.

## Preserved boundaries

- Analyzer execution remains explicitly human-authorized by `review:intelligence`.
- IntelOwl and Cortex allowlists, feature flags, upstream credentials and policy enforcement remain server-side.
- Navigation does not execute analyzers automatically.
- Enrichment output is evidence, not proof of maliciousness or local compromise.
- Enrichment does not grant review, external-share, publication or responder authority.
- Empty or unavailable history does not establish upstream absence or service health.

## Acceptance evidence

Repository-controlled acceptance is limited to static contract checks against the existing exact-head implementation and frontend compilation. The contract verifies persisted observable provenance, canonical context pivots, durable history reload and existing authorization/policy boundaries.

This evidence does not establish current upstream availability, staging or production-equivalent operation, owner usability acceptance, penetration-test results, independent assurance or production authorization.

# RUN-20260812-198 — RC13 Grafana datasource provisioning runtime failure

Date: 2026-08-12

## Trigger

During the accountable project-owner local retest after PR #160, `docker compose up --build` progressed beyond the earlier Grafana database-reader packaging blocker. `migrate` completed successfully, `grafana-db-provision` exited with code 0, and the DTMO API started successfully.

Grafana then failed its own provisioning startup and entered a restart loop with the owner-observed error:

```text
Datasource provisioning error: datasource.yaml config is invalid. Only one datasource per organization can be marked as default
grafana-1 exited with code 1 (restarting)
```

This prevents a healthy observability/graphics runtime and therefore blocks completion of the RC13 owner retest.

## Confirmed root cause

The repository contained two Prometheus datasource provisioning files simultaneously:

- `infrastructure/grafana/provisioning/datasources/prometheus.yml`
- `infrastructure/grafana/provisioning/datasources/dtmo-prometheus.yml`

Both declared the same datasource identity (`uid: dtmo-prometheus`) and both set `isDefault: true` for organization 1. Grafana 13.1.0 validates the complete provisioning directory and rejects multiple default datasources for the same organization.

The PostgreSQL intelligence datasource is explicitly `isDefault: false` and is not the cause.

## Test-gap finding

Repository tests had split ownership of the two files: RC12.2 validated `prometheus.yml`, while RC10.8 validated `dtmo-prometheus.yml`. Both files could therefore pass independently even though the combined runtime provisioning directory was invalid.

## Repair

Branch `rc13/grafana-datasource-provisioning-repair`:

- removes the obsolete duplicate `prometheus.yml`;
- makes RC12.2 validate the canonical `dtmo-prometheus.yml` used by RC10.8;
- adds a directory-wide contract requiring unique datasource UIDs per organization and at most one default datasource per organization;
- adds `RC13 Grafana Provisioning Runtime Gate`, which starts Grafana 13.1.0 with the complete DTMO provisioning and dashboard directories, requires `/api/health` with `database=ok`, and fails on datasource provisioning errors.

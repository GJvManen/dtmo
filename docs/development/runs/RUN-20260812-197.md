# RUN-20260812-197 — RC13 local Compose startup packaging blocker

Date: 2026-08-12

## Trigger

During the accountable project-owner post-merge retest of PR #159, a fresh repository clone was started with `docker compose up --build`. The Compose startup failed before the repaired console could be functionally re-accepted.

Observed runtime failure:

```text
grafana-db-provision-1 | python: can't open file '/app/tools/provision_grafana_reader.py': [Errno 2] No such file or directory
grafana-db-provision-1 exited with code 2
service "grafana-db-provision" didn't complete successfully: exit 2
```

## Confirmed root cause

`docker-compose.yml` starts `grafana-db-provision` with:

```text
python tools/provision_grafana_reader.py
```

The script exists in the repository, but the runtime `Dockerfile` copied only the application/package inputs, `backend`, and `database`. It did not copy `tools/provision_grafana_reader.py` into `/app/tools/`.

This is a repository packaging defect. It is not credited as a successful owner retest.

## Repair

Branch `rc13/compose-grafana-provisioner-packaging`:

- copies only the required Grafana reader provisioner into the runtime image;
- adds a static Dockerfile packaging assertion to the existing Grafana reader contract test;
- adds `RC13 Compose Runtime Packaging Gate`, which builds the canonical runtime image and verifies that `/app/tools/provision_grafana_reader.py` exists and compiles inside that image.

The repair is `PENDING_CI` until every returned workflow on the final exact PR head is `completed/success`.

## Repository inspection

The canonical read path is PostgreSQL-backed:

- `/api/v1/console/recent-intelligence` selects `IntelligenceItem` rows directly from PostgreSQL;
- `/api/v1/dashboards/summary` derives total intelligence, recent counts, average confidence, severity/source/review distributions and seven-day trend from `IntelligenceItem`;
- the unified console renders Intelligence, Overview KPIs and native analytics from those endpoints.

The built-in CISA connector path performs:

1. upstream fetch and parse;
2. `run_cisa_kev()` iteration over connector records;
3. `ingest_connector_record()` for each record;
4. raw object landing, canonical repository ingestion and OpenSearch indexing in `_persist_intelligence()`.

Before this repair, `ingest_connector_record()` contained:

```python
async for session in database.session():
    return await _persist_intelligence(...)
```

`Database.session()` is an async generator whose transaction logic is:

```python
yield session
await session.commit()
```

Returning from the loop body terminates the consuming coroutine without driving the generator through the statements after `yield`. The canonical commit can therefore be skipped even after `_persist_intelligence()` has produced an inserted/indexed receipt. This explains the owner-observed split between apparently successful loading and an empty canonical interface.

## Test-gap finding

`backend/tests/test_connector_ingestion_pipeline.py` replaced `ingest_connector_record()` with a fake and therefore validated connector call counts and synthetic receipt fields, but not the real transaction lifecycle or durable canonical visibility.

`backend/tests/test_rc13_1_source_to_intelligence.py` validated the console read projection with a fake session, but did not prove the live connector path commits before returning.

The two contracts could therefore both pass while the real bridge between them was transactionally incomplete.

## Bounded repair

Branch: `rc13/canonical-connector-commit-visibility`

Changes at record creation:

- retain the `IntelligenceIngestResponse` while `database.session()` is consumed to completion;
- return the connector receipt only after the session generator has executed its commit path;
- let commit failures propagate rather than reporting successful ingestion;
- add `backend/tests/test_rc13_connector_commit_visibility.py` covering:
  - commit-before-return;
  - commit-failure propagation;
- add `RC13 Canonical Connector Commit Visibility Gate` covering the new regression test plus connector ingestion, source-to-intelligence console and graphical-dashboard contracts.

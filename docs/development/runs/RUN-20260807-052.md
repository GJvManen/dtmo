# RUN-20260807-052 — RC7.4 payload provenance and normalization enforcement

## Plan

**Bounded objective:** implement and independently evidence immutable payload provenance and fail-closed normalization at the connector ingestion boundary, in Phase 4 roadmap order.

Blocking gates for this run:

- every accepted candidate retains source URI, optional source timestamp, fetch timestamp, connector ID, run ID, SHA-256 payload digest, confidence and raw evidence;
- malformed and duplicate records are quarantined rather than accepted;
- successful normalization, candidate acceptance and quarantine never imply publication approval;
- the dedicated workflow is observable on pull requests/manual execution, retains machine-readable evidence and fails closed when the primary provenance job is missing or unsuccessful;
- existing RC4/RC6/RC7 regression gates must execute on the exact PR head before acceptance.

External issue #1 remains authoritative for production credentials, provider-enforced limits, licences/terms, staging/deployment acceptance and independent assurance.

## Do

Implemented `backend/dtmo/connectors/provenance.py` with immutable ingestion context, candidate and quarantine dataclasses. Canonical JSON SHA-256 binds accepted records to raw payload content. Source/fetch/connector/run/confidence metadata is copied to every candidate, and all publication flags are hard-coded false.

`normalize_connector_records()` rejects invalid ingestion contexts before processing, quarantines non-object records, records without an external ID, malformed supplied source timestamps and duplicate external IDs, and never turns connector success into publication approval.

Added focused regression tests in `backend/tests/test_rc7_payload_provenance.py`, workflow-contract regression protection in `backend/tests/test_rc7_payload_provenance_workflow.py`, deterministic evidence generation in `tools/validate_payload_provenance.py`, and `.github/workflows/payload-provenance.yml` with retained `payload-provenance-evidence` plus an independent fail-closed aggregate gate.

Public threat/advisory review for this objective: no newly found public advisory changed the ingestion-provenance control design. The approved CISA KEV source remains treated as authoritative-source input under the already accepted RC7.3 connector contract; current public-search results did not provide a more specific fresh advisory requiring a code-scope deviation. Provenance confidence therefore remains based on the configured connector contract, not inferred from this run.

## Check

At documentation time, the new branch code is committed but exact-head GitHub Actions evidence has not yet been observed. No test or workflow is marked PASS merely because it exists.

Expected dedicated evidence must prove: `decision=pass`, HTTPS source URI, 64-character payload digest, retained source/fetch/run identity, confidence 95 for the governed fixture, duplicate quarantine, malformed/missing-ID quarantine and `publish_approved=false` for aggregate, candidate and quarantine evidence.

## Act

Lesson: connector-level provenance is insufficient unless each candidate is cryptographically bound to its raw payload and run/fetch context before persistence or downstream transformation. The release gate therefore validates payload-level provenance independently and retains evidence for later audit.

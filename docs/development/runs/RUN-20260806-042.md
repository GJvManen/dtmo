## Check

Recovery Gate #1 failed during OpenSearch service initialization because the image entrypoint security installer was not disabled. That was corrected with `DISABLE_SECURITY_PLUGIN=true`.

Recovery Gate #3 then started PostgreSQL and OpenSearch successfully, migrated and seeded the canonical database, and created the clean target index. The first document write returned HTTP 400. The target used root `dynamic: strict`, while `provenance` was declared only as an enabled object without explicit child properties. The immutable provenance fields were therefore rejected as undeclared dynamic fields. No evidence file was produced, the artifact upload failed as designed, and the recovery gate remained fail-closed.

The mapping now explicitly permits only `source_url`, `content_hash`, `source_reliability`, `is_primary_source` and `content_integrity_verified`, all with fixed types and nested `dynamic: strict`. No broad dynamic mapping or provenance relaxation was introduced.

## Act

Lesson: a strict root mapping is insufficient when nested evidence objects are not fully declared. Recovery projections must enumerate provenance fields explicitly, and failed remote responses must retain their server-provided error body for diagnosis.

# RUN-20260806-007 — Harden manual CI observation evidence

- **Started:** 2026-08-06 03:42 CEST
- **Workstream:** Phase 1 — CI and workflow integrity
- **Objective:** Prevent a manually dispatched observer run from being mistaken for independent evidence of an RC4 Quality Gate execution.
- **Bounded scope:** Harden `.github/workflows/ci-observer.yml` and its regression contract only; do not advance Phase 1 without actual Actions evidence.

## PLAN

The existing observer supported `workflow_dispatch`, but a manual invocation defaulted the observed run ID, SHA and URL to the observer itself. That could create structurally valid-looking evidence without identifying a real `RC4 Quality Gate` run.

### Blocking gates

| Gate | Method | Blocking |
|---|---|---:|
| Manual evidence identifies a real quality-gate run | Required dispatch inputs and validation | Yes |
| Automatic workflow-run observation remains supported | Preserve `workflow_run` trigger | Yes |
| Evidence is machine readable | JSON artifact with explicit schema | Yes |
| Observer stays least-privileged | `actions: read`, `contents: read` | Yes |
| Regression protection covers the hardened contract | Parsed YAML assertions | Yes |
| Actual execution evidence exists | GitHub Actions run plus artifacts | Yes |

## DO

- Added required manual dispatch inputs for observed run ID, conclusion, full head SHA and canonical run URL.
- Removed fallback behaviour that treated the observer's own run metadata as the observed quality-gate run.
- Added strict shell validation for numeric run IDs, 40-character commit SHAs and repository-scoped GitHub Actions run URLs.
- Replaced hand-built JSON with Python JSON serialization.
- Added `schema_version`, `observer_head_sha` and `observed_workflow` fields to the evidence document.
- Expanded the workflow regression test to protect required inputs, validation patterns and evidence fields.

## ACT

### Lesson

A manual observer control must never be able to self-attest by silently substituting its own execution metadata for the release-critical workflow it claims to observe. Manual evidence must explicitly identify and validate the upstream run.

### Release decision

- **Bounded run:** `BLOCKED` because the hardened contract is committed but has not executed in GitHub Actions.
- **Phase 1:** `BLOCKED`.
- **Overall release:** `CI VALIDATION PENDING`.

### Unresolved blocker

Repository Actions execution remains externally unverified. Required evidence is one completed `RC4 Quality Gate` run with `workflow-contract-evidence`, followed by a matching `RC4 CI Observer` run with `ci-observation-evidence` for the same head SHA.

### Exactly one next priority

Obtain and verify one real `RC4 Quality Gate` workflow run and both named evidence artifacts for the same commit SHA; do not add further CI structure until execution visibility is demonstrated.

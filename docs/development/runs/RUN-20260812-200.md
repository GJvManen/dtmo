## New blocker

During the same functional retest, `POST /api/v1/admin/sources/catalog/bootstrap` returned HTTP 500.

Repository inspection confirmed a cross-component contract mismatch:

- `backend/dtmo/source_catalog.py` defines Cisco's logical credential reference as `env:CISCO_OPENVULN_TOKEN`;
- `backend/dtmo/credentialed_source_executor.py` resolves the executable `env:VARIABLE` form;
- `backend/dtmo/sources.py` accepted only `vault://`, `secret://` or `env://` references at registry write time.

The supported Cisco catalog entry therefore failed registry creation before the source catalog could bootstrap.

## Repair scope

The bounded repair:

1. introduces one registry secret-reference validator/canonicalizer;
2. accepts the executable canonical `env:VARIABLE` form;
3. normalizes legacy `env://VARIABLE` input to `env:VARIABLE` so registry-valid input cannot later be runtime-invalid;
4. retains logical `vault://` and `secret://` references;
5. continues rejecting raw secret values and malformed references;
6. makes the credentialed executor consume the same canonicalization boundary;
7. adds an integration-style catalog bootstrap test proving all supported sources bootstrap idempotently, disabled by default;
8. adds an exact-head RC13 Source Catalog Bootstrap Gate.

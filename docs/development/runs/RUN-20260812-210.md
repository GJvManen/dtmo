## Product requirement

- more colour in Overview using green/yellow/red severity semantics;
- filters for informational, low, medium and high risk/severity;
- the same filtering in Intelligence;
- framework mapping later, without inventing mappings now.

## Repository findings

The pre-change canonical console:

- rendered severity cards with a neutral status pill;
- rendered all chart bars with one generic colour;
- had no shared severity filter state;
- loaded recent intelligence directly from canonical PostgreSQL;
- loaded Overview severity/KPI summary from canonical PostgreSQL dashboard queries;
- already supported a single server-side severity parameter on governed OpenSearch intelligence search.

## Implementation

### Shared canonical severity set

The enhancement uses the existing `IntelligenceSeverity` enum:

- informational;
- low;
- medium;
- high;
- critical.

No new severity taxonomy or reclassification logic is introduced.

### Overview

A shared multi-select severity filter is added to Overview. The selected set controls canonical PostgreSQL-backed:

- Intelligence total;
- New intelligence in the previous 24 hours;
- Average confidence;
- Overview severity distribution;
- Overview recent-intelligence cards.

Source/catalog and connector operational metrics are intentionally not severity-filtered.

### Intelligence

The same filter state is rendered in Intelligence and synchronized with Overview.

Recent canonical intelligence is filtered server-side against PostgreSQL.

Search uses the existing OpenSearch `severity` query parameter when exactly one severity is selected. For a multi-select state, returned results are additionally filtered against the selected canonical severities in the browser.

### Accessibility

Severity is not encoded by colour alone. The interface retains:

- textual severity names;
- labelled native checkboxes;
- accessible filter group labels;
- live filter-state text;
- visible focus;
- textual chart labels;
- count tables;
- truthful filtered-empty states.

### Architecture

A new bounded composition router builds on the accepted RC13 Governance + Administration page and wins the canonical `/` and `/ui/console` route order while preserving the underlying RC13 routers for their API/JavaScript resources.

New canonical read endpoint:

- `/api/v1/console/severity-summary`.

The existing `/api/v1/console/recent-intelligence` path is composed with repeatable optional `severity` query parameters.

Unknown severity values fail closed.

## Security and governance invariants

Unchanged:

- server-side RBAC;
- least privilege;
- human/service-account separation;
- review authority;
- separate external share approval;
- source execution authority;
- provenance;
- auditability;

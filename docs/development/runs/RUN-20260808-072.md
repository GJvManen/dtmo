## Check

The accepted RC8.1 profile defines 40 searches/s, search p95 <= 800 ms, search p99 <= 1,500 ms and error rate <= 1%. This implementation reads those thresholds directly from the machine-readable profile.

The CI corpus is deliberately scaled to 5,000 synthetic documents for bounded regression execution and is explicitly recorded as `scaled_ci_fixture=true`; it does not represent the accepted 1,000,000-record production-readiness envelope and cannot satisfy the external load/stress gate in issue #1 by extrapolation alone.

Every returned hit must retain `external_id` and `source_uri`, and must retain `publish_approved=false`. Missing provenance, publication-approved hits, HTTP failures or budget violations fail the measurement.

Vendor review: the official OpenSearch version history lists 2.19.6 (2026-07-02) as the current 2.19 patch and states that it includes security updates and infrastructure maintenance. The inherited recovery topology still uses 2.19.1, so this new RC8.3 workflow was pinned to 2.19.6 rather than extending the older patch into new performance evidence. Provenance: official OpenSearch documentation; confidence: high. A separate 2026 OpenSearch advisory concerned compromised unreleased JavaScript client development packages and explicitly stated stable releases were not affected; it does not change this server-side harness design.

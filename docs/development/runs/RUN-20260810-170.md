## Threat/advisory review

This control-plane change treats source URLs as untrusted configuration because connector registries are a natural SSRF and secret-exposure boundary. The implementation follows a fail-closed allowlist-style scheme/host/port policy. DNS-resolution and redirect-time validation are explicitly deferred with execution rather than falsely claimed here. Existing CISA KEV provenance remains authoritative for the built-in connector. The previously recorded OpenSearch 2.19.x patch-maintenance finding remains open as a separate dependency objective.

## Act

Lesson: source lifecycle configuration and connector execution must be separate trust boundaries. Persisting a source definition is safe only if registration cannot itself become an unbounded network primitive.

Backlog update: after exact-head CI acceptance, the next single priority is a **safe generic source execution adapter** that can execute enabled registered JSON feeds with DNS/rebinding-safe egress validation, bounded responses, provenance normalization, health/replay integration and admin test-run evidence. Dashboard integration remains immediately after the source execution plane.

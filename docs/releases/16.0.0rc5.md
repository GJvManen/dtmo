# DTMO 16.0.0rc5

Status: release candidate — exact-head CI required before merge/acceptance.

## Highlights

- New governed DTMO operational console at `/` and `/ui/console`.
- Consolidated runtime health, connector status, intelligence search, review/share governance, audit evidence and CISO token revocation.
- Responsive, keyboard-visible, reduced-motion aware interface with skip navigation and live status regions.
- Strict same-origin CSP and no-store handling for dynamic console HTML/JavaScript.
- Local/dev/staging test identity is limited to per-tab `sessionStorage`; bearer tokens are not persisted.
- Existing dedicated role pages remain available.
- Application and package version advanced to `16.0.0rc5`.
- Docker Compose now passes the required external `OPENSEARCH_INITIAL_ADMIN_PASSWORD` into OpenSearch.
- `.env.example` documents the OpenSearch bootstrap input without providing a runnable secret default.
- New regression contract in `backend/tests/test_frontend_console.py` and QA gate in `docs/qa/FRONTEND_RELEASE_GATE.md`.

## Access after startup

- DTMO Console: `http://localhost:8000/`
- OpenAPI: `http://localhost:8000/docs`
- Health: `http://localhost:8000/health`
- Metrics: `http://localhost:8000/metrics`
- AIStor/MinIO Console: `http://localhost:9001/`
- Prometheus: `http://localhost:9090/`

## Claim boundary

This release candidate does not close genuine VoiceOver/NVDA validation, real staging deployment parity, penetration testing or other external production-acceptance gates. Those remain separately evidenced requirements.

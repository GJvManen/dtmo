# DTMO 16.0.0rc8

Status: `CI_VALIDATION_PENDING`

## Theme

Governed Admin Configuration & Source Registry.

## Added

- persistent source registry (`source_definitions`, migration `0007_source_registry`);
- human-admin source lifecycle API at `/api/v1/admin/sources`;
- professional source administration workspace at `/ui/admin-sources`;
- source type, reliability, enablement and polling-interval configuration;
- approved secret references instead of embedded credentials;
- first-line SSRF-safe endpoint registration policy;
- persistent audit-chain records for source create/update;
- regression tests for admin/service-account separation, unsafe URL rejection, secrets, migration and UI/API wiring.

## Security model

A principal needs `manage:connectors` **and** the human `admin` role to mutate the registry. Service accounts are intentionally excluded from the human admin control surface. This release does not alter intelligence review, share approval or publication policy.

Endpoint registration accepts HTTPS public-host shapes only and rejects local/internal names, non-global literal IPs, embedded credentials and non-default HTTPS ports. This is registration-time validation, not a complete runtime SSRF defense.

## Important execution boundary

`json-feed` sources can be registered and governed but are not fetched in rc8. A later bounded adapter must add DNS/rebinding-safe destination validation, redirect handling, response limits, content validation, provenance normalization, connector health/failure isolation and replay semantics before generic execution is enabled.

## Upgrade

Apply Alembic migrations through `0007_source_registry` before using the admin registry.

## Acceptance

No release PASS is claimed until every registered workflow succeeds on the final exact PR head. Real staging, VoiceOver/NVDA, penetration testing, external assurance and production go/no-go remain outside this release claim.

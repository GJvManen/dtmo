## Release objective

`16.0.0rc12` established the consolidated DTMO engineering baseline that was originally intended for external staging validation:

- one canonical unified DTMO console;
- governed source administration and execution;
- completed onboarding for the current operational vendor catalog;
- integrated threat intelligence investigation and governance foundations;
- Grafana operational and intelligence dashboards;
- dedicated least-privilege Grafana reporting access;
- same-origin `/grafana/` gateway capability;
- retained accessible native analytics alternatives;
- completed repository-controlled CI, security, recovery, performance and observability acceptance.

RC13 subsequently establishes that normal product analytics must be native and usable in the DTMO session without a separately authenticated Grafana embed being required.

## Architecture baseline

The reference architecture uses:

- Python 3.12+ and FastAPI for application/API services;
- PostgreSQL for relational state and governed reporting views;
- OpenSearch for search/index state;
- Redis for cache/queue state;
- S3-compatible object evidence storage;
- Prometheus for metrics;
- Grafana for authenticated operational/intelligence analytics;
- Nginx as the managed browser gateway.

## Source framework

The current operational vendor catalog is connected through governed built-in or unified-framework adapters. The authoritative integration contract is [`SOURCE_CONNECTION_MATRIX.md`](../qa/SOURCE_CONNECTION_MATRIX.md).

Credentialed source definitions carry logical secret references only. Runtime credentials are not persisted in the catalog or repository evidence.

## Security and governance

- server-side RBAC remains authoritative;
- source execution, analysis and dashboard access do not grant publication authority;
- human review and external share approval remain distinct decisions;
- separation of duties is preserved;
- Grafana anonymous access is disabled;
- Grafana intelligence reporting uses dedicated least-privilege reporting views/identity;
- provenance, privacy, auditability and fail-closed execution requirements remain in force.

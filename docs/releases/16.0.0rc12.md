# DTMO 16.0.0rc12 — Release Candidate Notes

Release family: **16.0.0rc12**  
Engineering baseline: **PASS**  
Functional unified-console acceptance: **RC13 PASS / OWNER_ACCEPTED**  
Production readiness: **Phase 8 pending; not production ready**

## Release purpose

`16.0.0rc12` is the consolidated DTMO release-candidate engineering baseline for an education-focused Cyber Threat Intelligence platform. It combines the canonical application, governed source operations, intelligence persistence/search, native analytics, controlled Administration/RBAC, Governance knowledge and operational observability into one tested platform baseline.

## Product highlights

### Unified DTMO console

The release provides a canonical application shell with:

- Overview;
- Intelligence;
- Sources & Catalog;
- Visual Analytics;
- Administration;
- Governance.

The product is functionally owner-accepted after the RC13 acceptance program.

### Canonical intelligence pipeline

The accepted pipeline preserves distinct responsibilities:

- raw source/evidence objects in S3-compatible storage;
- durable canonical intelligence in PostgreSQL;
- search/index representation in OpenSearch;
- Redis coordination/cache/queue state;
- application dashboards/analytics derived from canonical state.

Durable connector success requires the canonical database commit boundary; search-index or raw-object success alone is not treated as canonical application success.

### Source operations

The release includes:

- curated source catalog and bootstrap;
- enabled/disabled source state;
- supported source execution profiles;
- credentialed source execution using logical secret references;
- source state/freshness/runtime evidence;
- normalized supported item types and canonical references;
- provenance/raw evidence retention.

### Analytics and observability

Normal user analytics are native DTMO views. Prometheus and separately authenticated Grafana provide operational/advanced observability without introducing anonymous access or a second-login dependency for normal product analytics.

### Administration and identity

The release includes managed principal/role assignments with server-side authorization, human/service-account separation, administrator safety controls and auditable privileged state changes.

Production bearer tokens remain externally issued and cryptographically validated; local managed assignment state does not silently mint or rewrite active production token claims.

### Governance

The Governance surface exposes repository-backed framework/governance knowledge while preserving truthful coverage states. Current external mapping state remains deliberately conservative:

- Normenkader IBP — `UNMAPPED` first-class control crosswalk;
- MITRE ATT&CK — `UNMAPPED` first-class technique crosswalk;
- CVSS — `CONTEXT_ONLY`;
- DTMO internal governance — repository-backed internal mappings.

## Security properties

The release preserves:

- RBAC and least privilege;
- strict human/service-account separation;
- administrator self-management/final-admin safeguards;
- provenance and confidence preservation;
- privacy/data minimization;
- logical secret references rather than raw repository credentials;
- separate human review and external-share approval;
- no automatic publication authority from source execution, analytics, CI, Administration, Governance or staging access;
- fail-closed framework mapping and evidence claims.

## Quality and acceptance model

The release line uses exact-head CI. Automated evidence covers build/quality, security/identity, connector reliability, recovery, performance, accessibility/browser behavior, observability/operations, source/persistence contracts, functional console behavior and open-source governance.

Repository CI is not treated as a substitute for accountable functional owner acceptance or real external staging evidence.

RC13 functional product acceptance is complete. Phase 8 staging validation is the next production-readiness gate.

## Known limitations and planned enhancements

The accepted product is functional, but the following enhancements are planned:

- richer accessible severity colours and informational/low/medium/high filtering;
- manual governed source onboarding;
- configurable trend analysis;
- first-class provenance-backed Normenkader IBP / MITRE ATT&CK / CVSS mapping structures;
- deeper Administration role/permission management;
- deeper Governance framework/evidence drill-down.

These are tracked separately from production-readiness acceptance.

## Phase 8 boundary

Before this release family can be treated as a production candidate deployment, DTMO requires a real approved production-equivalent staging environment tied to one immutable deployment identity and supported by configuration, identity/secrets, TLS/network, data-handling, rollback/change and deployment-time security evidence.

The local development object-storage bootstrap/admin credential compatibility exception must not be reused in staging. Staging application identities must be separate and least-privilege.

## Production boundary

`16.0.0rc12` is **not approved for production** until:

1. Phase 8 real staging is accepted;
2. Phase 9 independent external assurance is accepted;
3. Phase 10 formal production go/no-go is completed.

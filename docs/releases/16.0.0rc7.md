# DTMO 16.0.0rc7 — Intelligence pipeline recovery

## Purpose

16.0.0rc7 restores the functional intelligence path discovered broken during external/local acceptance of rc6. The release is intentionally bounded to search and the existing CISA KEV connector; admin configuration/source-registry UX and graphical dashboards are subsequent objectives.

## Changes

- fresh OpenSearch deployments self-initialize the intelligence index before search;
- strict OpenSearch mappings now match canonical confidence fields;
- search sorting uses `confidence_score`;
- connector records now pass through raw-object landing, canonical persistence, provenance and OpenSearch indexing;
- connector replay performs idempotent search-index repair;
- manual CISA KEV execution requires `manage:connectors`;
- connector/service ingestion does not grant review or external share approval;
- regression tests cover the search runtime contract and connector ingestion orchestration.

## Operator note

Automatic polling still requires `DTMO_FEATURE_LIVE_CONNECTORS=true`. The existing CISA KEV connector can also be run through its governed API endpoint by a principal with `manage:connectors`. Arbitrary source registration is intentionally not enabled in this release.

## Security and governance

RBAC, least privilege, separation of duties, provenance, raw-evidence hashing, privacy, append-only auditability and human share approval remain mandatory. A connector can ingest candidate intelligence but cannot review or approve it for sharing.

## Dependency/advisory note

OpenSearch official version history shows later 2.19 patch releases than the currently deployed 2.19.1, including security updates. The dependency upgrade is deliberately not bundled into this functional remediation and remains a separate production-readiness item requiring compatibility and security validation.
